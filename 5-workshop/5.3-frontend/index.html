Deploy the frontend layer

In this section, you will deploy the React frontend using Amazon S3 and Amazon CloudFront.

  • Amazon S3 stores all static files generated by the React application.
  • Amazon CloudFront acts as a Content Delivery Network (CDN), delivering those files to users with lower latency, improved performance, and enhanced security.

Unlike traditional static website hosting, the S3 bucket remains completely private. End users cannot access the bucket directly. Instead, CloudFront is granted permission to retrieve objects through Origin Access Control (OAC).

Step 1. Create an S3 Bucket

  1. Open the Amazon S3 Console.

  2. Choose Create bucket.

  3. Configure the bucket using the following settings:

PropertyValue
Bucket namefcj-recsys-frontend-<your-name>
AWS RegionAsia Pacific (Singapore) ap-southeast-1
Block Public AccessKeep all options enabled
  1. Choose Create bucket.

Many older tutorials recommend enabling Static Website Hosting and making the bucket public.

This approach is no longer recommended by AWS because it exposes the bucket directly to the Internet.

Throughout this workshop, the bucket remains private, and only CloudFront is allowed to access its contents.

Step 2. Build the Frontend

Navigate to the frontend directory and build the application.

cd frontend
npm install
npm run build

After the build completes, Vite generates the following directory:

dist/

This folder contains all static assets that will be uploaded to Amazon S3.

At this stage, you do not need to configure the backend API endpoint.

After completing Section 5.5 (API Gateway), you will configure the VITE_API_BASE_URL environment variable and rebuild the application.

Step 3. Upload Files to Amazon S3

Upload the build output using the AWS CLI.

aws s3 sync dist/ s3://fcj-recsys-frontend-<your-name>/ --delete

The

--delete

option removes obsolete files from previous deployments, ensuring that the bucket always matches the latest build.

After the upload finishes, your bucket should have a structure similar to:

index.html
assets/
favicon.ico
...

Step 4. Create a CloudFront Distribution

Open the CloudFront Console.

Choose Create distribution.

Origin

Configure the origin as follows:

PropertyValue
Origin domainYour S3 bucket
Origin accessOrigin Access Control (recommended)

Choose Create new OAC.

Keep the default configuration and choose Create.

Default Cache Behavior

Configure the following settings:

PropertyValue
Viewer protocol policyRedirect HTTP to HTTPS
Allowed HTTP methodsGET, HEAD

Settings

Configure:

PropertyValue
Default root objectindex.html

Finally, choose Create distribution.

Step 5. Grant CloudFront Permission to Access the Bucket

After the distribution is created, CloudFront displays a message asking you to update the bucket policy.

Perform the following steps:

  1. Choose Copy policy
  2. Open the Amazon S3 Console
  3. Select your bucket
  4. Open the Permissions tab
  5. Choose Bucket Policy
  6. Select Edit
  7. Paste the copied policy
  8. Choose Save changes

This policy grants read-only access exclusively to the CloudFront distribution.

Step 6. Configure Custom Error Pages for React Router

React applications use client-side routing.

For example:

https://domain.com/cart

CloudFront attempts to retrieve:

/cart

from Amazon S3.

Since no such object exists, CloudFront returns either:

403 Forbidden

or

404 Not Found

To resolve this issue:

Navigate to:

Error pages → Create custom error response

Create the following configuration:

PropertyValue
HTTP error code403
Customize error responseYes
Response page path/index.html
HTTP response code200

Repeat the same configuration for:

404 Not Found

This allows React Router to handle routing correctly.

Step 7. Configure Environment Variables

This project uses Vite, so every client-side environment variable must begin with:

VITE_

Create the following file:

frontend/.env

Example:

VITE_API_BASE_URL=https://xxxxx.execute-api.ap-southeast-1.amazonaws.com

For production deployments, create:

.env.production

to separate production settings from your development environment.

Environment Variable Rules

TypePrefixAccessible in Browser
Public VariableVITE_Yes
Private VariableOtherNo

Example:

# Correct
VITE_APP_TITLE=My Store

# Incorrect
VITE_STRIPE_SECRET=sk_live_xxx

Never store API keys, secret keys, database credentials, or other sensitive information in variables prefixed with VITE_.

These values are bundled into the JavaScript files and can be viewed by anyone using the browser.

Step 8. Global State Management with Redux Toolkit

This project uses Redux Toolkit instead of React Context API to manage global application state.

Benefits

  • Reduces unnecessary component re-renders.
  • Simplifies asynchronous operations.
  • Integrates with Redux DevTools.
  • Scales well for large applications.

Example project structure:

store/
├── slices/
│   ├── authSlice.ts
│   ├── cartSlice.ts
│   ├── productsSlice.ts
│   └── uiSlice.ts
└── store.ts

Example using createAsyncThunk:

export const fetchProducts = createAsyncThunk(
  "products/fetch",
  async (_, { rejectWithValue }) => {
    try {
      const response = await api.get("/products");
      return response.data;
    } catch (err: any) {
      return rejectWithValue(err.response.data);
    }
  },
);

Step 9. JWT Authentication Security

For demonstration purposes, the JWT access token can be stored in:

localStorage

to simplify development.

However, this approach is not recommended for production because it is vulnerable to Cross-Site Scripting (XSS) attacks.

Comparison

Storage MethodAdvantagesDisadvantagesSecurity
localStorageEasy to implementVulnerable to XSSLow
HttpOnly CookieNot accessible via JavaScriptRequires CSRF protectionHigh
Memory + Refresh TokenHighest securityMore complex implementationVery High

For production environments, it is recommended that AWS Lambda sets cookies with:

HttpOnly
Secure
SameSite=Strict

The frontend does not need to store JWT tokens explicitly because browsers automatically include secure cookies with each request.

Step 10. Performance Optimization

Several optimization techniques are used throughout the project:

  • React.memo
  • useMemo
  • useCallback

Example:

const filteredProducts = useMemo(() => {
  return products.filter((p) => p.category === selectedCategory);
}, [products, selectedCategory]);

const handleAddToCart = useCallback((product: Product) => {
  dispatch(addToCart(product));
}, []);

For applications with hundreds of products, additional optimizations are recommended:

  • Lazy Loading
  • Virtual Scrolling
  • Code Splitting
  • Lazy Image Loading
